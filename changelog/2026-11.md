# November 2026

## 2026-11-18

### Added
- **Cancel subscriptions** — customers can cancel an active, trialing, past due
  or paused plan from the customer portal (Subscriptions → Cancel subscription,
  with a confirm step). Store owners can cancel through the API with
  `POST /api/v1/subscriptions/{id}/cancel` (and list with
  `GET /api/v1/subscriptions`) and through the MCP tools `list_subscriptions` and
  `cancel_subscription`. New `subscriptions:read/write` API key scopes (write
  means cancel; there is no delete). Cancelling stops billing at PayPal or Stripe
  immediately, sets the status to `cancelled` with `cancelledAt` and
  `cancelledBy`, fires the `subscription_cancelled` webhook, and emails the
  customer. Repeating a cancel is safe. No schema migration.

### Fixed
- Cancelling a Stripe-linked subscription from the dashboard now cancels it at
  Stripe too; before, only the Paymug status changed and Stripe kept billing.

## 2026-11-17

### Added
- **Migrate from Polar, Paddle and Dodo Payments** — new source cards on
  **Settings → Migrate**, on the same free, chunked, resumable and idempotent
  runner. Polar imports products with a variant per price, license and GitHub
  benefits, orders, license keys with activations, discounts and subscriptions
  (downloadable files need a re-upload: the Polar API has no file URLs). Paddle
  imports products and prices, customers, transactions (one order per line
  item) with refund adjustments, discounts and subscriptions with card brand,
  last four and Paddle IDs. Dodo Payments also imports digital files from fresh
  presigned URLs, license keys with instances and entitlement settings; its
  subscriptions are re-subscribe only until a card export is confirmed. Stripe
  import mapping file upload links subscriptions by exact ID, per-row cancel at
  the source (end of period), `/api/compat/polar/...` and `/api/compat/dodo/...`
  license API shims, MCP tool `migrate_from_source`, and
  `orders.gateway` values `polar`, `paddle` and `dodo`. No schema migration.
  See the guides for [Polar](../docs/guides/migrate-from-polar.md),
  [Paddle](../docs/guides/migrate-from-paddle.md) and
  [Dodo Payments](../docs/guides/migrate-from-dodo-payments.md).
- **Migrate from Lemon Squeezy** — free **Settings → Migrate** page. Paste an API
  key, preview counts and conflicts, and import products, variants, files,
  customers, orders, license keys and activations, discounts, affiliates and
  subscriptions (as `migration_pending`). Chunked, resumable and idempotent;
  failures CSV and ID mapping download. Migration `0034_lemonsqueezy_migration`
  adds `product_variants`, `migration_jobs`, `orders.variant_id/variant_name`
  and `source/source_id` columns, and converts existing product `options` into
  variants with the same IDs. New `migrations:read/write` API key scopes. See
  [`docs/guides/migrate-from-lemonsqueezy.md`](../docs/guides/migrate-from-lemonsqueezy.md).
- **Product variants** — each variant overrides price, billing, trial, files,
  license and delivery settings; the product holds defaults. Stripe, PayPal
  (including subscriptions), SePay and free checkout, fulfillment and licenses
  use the chosen variant. Orders record `variantId` / `variantName`; products in
  the API include `variants`; `/buy/<product>?variant=<id>` preselects one.
  Saving price options in the product editor keeps variants in sync.
- **Variant overrides editor** — per-variant pay-what-you-want (with minimum),
  billing and trial, license, delivery, GitHub and files, with inherit toggles.
  `GET/POST /api/products/{id}/variants` and `PATCH/DELETE .../{variantId}`.
  Store backups now include variants; revenue by variant on **Analytics**.
- **Subscription migration** — link imported card subscriptions to Stripe (dry
  run first, first charge on the original renewal date), email PayPal customers a
  signed re-subscribe link, and cancel the Lemon Squeezy copy per row. MCP tools
  `migrate_from_lemonsqueezy`, `advance_migration`, `get_migration_status`; the
  scheduled worker resumes stalled imports.
- **Lemon Squeezy license API shim** — `POST /api/compat/lemonsqueezy/v1/licenses/{validate,activate,deactivate}`
  accepts the Lemon Squeezy request/response shape so sellers' apps only change
  their base URL.
- **Stripe Tax** — new **Dashboard → Settings → Tax** page to enable automatic
  tax calculation on Stripe checkout sessions. Per-store setting. Migration `0033_stripe_tax`.

## 2026-11-11

### Added
- **MCP server** — stateless endpoint at `POST /api/mcp` exposing tools for
  products, categories, orders, and customer / discount / license / subscriber
  records. Tools are filtered by the calling API key's permissions.
- **Scoped API keys** — per-resource read / write / delete scopes, with a
  permissions picker in the API keys UI. Scopes are enforced on `/api/v1`
  endpoints. Existing keys keep read-only access to products, orders, and
  customers. Migration `0032_api_key_scopes`. See
  [`docs/guides/api-keys.md`](../docs/guides/api-keys.md).
- **SEPay payments** — connect SEPay in **Settings → Payments**, hosted checkout
  button, webhook handler, and a pending-confirmation page on checkout success.
  New env vars in `.env.example`; see
  [`docs/guides/payment-setup.md`](../docs/guides/payment-setup.md).

### Changed
- Dashboard overview stats and database queries reworked for faster loading.
- Icon set updated across dashboard, customer portal, checkout, and setup screens.
- Added `yarn.lock` and `.yarnrc.yml` for Yarn installs.

### Fixed
- Minor layout fix in the customer profile details view.
